# Telegram Premium Custom Emoji setup

## What changed
- Added `custom-emoji.js` and installed it in `bot.js`.
- Plain-text `sendMessage` / `editMessageText` and supported media captions automatically receive Telegram `custom_emoji` entities.
- Existing Markdown/HTML messages are intentionally left unchanged. Telegram Bot API does not allow `parse_mode` together with explicit `entities`; removing parse_mode would break the bot's existing Markdown formatting.

## Configure IDs
1. Obtain the actual `custom_emoji_id` for each emoji from a Telegram custom emoji message/pack using a bot or tool that exposes message entities.
2. In Render: open your service → Environment → Add Environment Variable.
3. Set `CUSTOM_EMOJI_MAP` to a JSON object mapping the exact Unicode placeholder emoji to its ID. Example format:

   `{"⭐":"YOUR_REAL_ID","🔥":"YOUR_REAL_ID"}`

   Do not use the sample IDs unless they are confirmed IDs belonging to your emoji pack.
4. Save changes and redeploy/restart the bot.

For local hosting, add the same line to `.env` (not `.env.example`):
`CUSTOM_EMOJI_MAP={"⭐":"YOUR_REAL_ID","🔥":"YOUR_REAL_ID"}`

## Important limitations
- A custom emoji ID is not generated by the code; it must be a real ID provided by Telegram.
- The mapped Unicode character must appear in the outgoing text exactly as configured.
- Existing messages that set `parse_mode: 'Markdown'` or `'HTML'` keep their current formatting and display regular Unicode emoji. To use custom emoji in a particular Markdown message, that message must be converted to explicit Telegram entities (including its formatting entities) rather than mixing `parse_mode` and `entities`.
- No bot code can force a non-premium/non-allowed custom emoji to display for every recipient. Telegram controls custom emoji availability and rendering.
